# parquet-viewer L2 — Registration writes the ShellEx association before the in-process server keys, with no rollback

- Severity: low
- Pinned SHA verified: `e815e646e6d261291417730ac79345da81e7f6f9`
- Status: **CONFIRMED** — write order in `register` is AppID `registration.rs:202` → DisplayName `:205` → PreviewHandlers `:208` → **ShellEx `:211`** → InprocServer32 default `:214` → ThreadingModel `:217`. No rollback on error; the wrapper maps any error to E_FAIL (`com.rs:476-479`).
- If a later write fails, `.parquet` points at a CLSID with no registered server — a dead association displacing the previously backed-up handler.
- Policy flag: **C1** (same family as L1: registration/uninstall contract).
- Size: S · Model effort: entry-level OK
- Depends on: L1 (same function; L1 first), and C1 ruling.
- Manager sign-off: not individually required beyond C1.

## Root cause
The important keys (the association) were written before the unimportant-looking ones (the server definition); combined with no error recovery, any failure mid-sequence leaves a poisoned association.

## Fix (minimal)
- Reorder the register sequence in `registration.rs:201-218` to: CLSID + AppID → InprocServer32 (default + ThreadingModel) → PreviewHandlers → **ShellEx last**.
- On error in `register`: best-effort restore — if ShellEx was not yet written, nothing to undo; if it was (keep it last so this branch is nearly dead), restore `previous` (already in scope) and return the error. Cap the effort at "restore previous ShellEx"; do not build a full transactional registry writer (rejected alternative — complexity far beyond a low finding).
