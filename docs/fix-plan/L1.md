# parquet-viewer L1 — Stale first-only backup lets uninstall erase a third-party handler's association

- Severity: low
- Pinned SHA verified: `e815e646e6d261291417730ac79345da81e7f6f9`
- Status: **CONFIRMED** (with one phrasing caveat) — `crates/windows/src/registration.rs:188-197`: BACKUP is written only when `get_string(BACKUP, "")` returns None, so a re-register after a third-party takeover keeps the old backup while the new `previous` ({OTHER}) is discarded. Unregister then sees ours + empty backup and falls to `:263-265` `delete_value(&shell, "")`, removing the third party's ShellEx association even though the installer promised "It will be backed up and restored" (`installer/Register-ParquetPreview.ps1:84`).
- Caveat recorded: this deletes only the association *value*; the foreign handler's CLSID registration survives. The practical loss is the user's working association.
- Policy flag: **C1 (uninstall policy across csv-viewer/parquet-viewer)** — the fix's trigger condition should match whatever C1 ruling applies to 07a's mirror logic.
- Size: S · Model effort: entry-level OK
- Depends on: C1 ruling (the pass/fail condition references foreign-vs-ours policy).
- Manager sign-off: not individually required beyond C1.

## Root cause
"Preserve the first backup" was written to protect the pristine pre-install state, but re-registration is not idempotent: the world changed since our install, and the code cannot tell by looking only at presence/absence of BACKUP.

## Fix (minimal)
- `registration.rs:188-197` (inside `register`): overwrite BACKUP when `previous` is a foreign CLSID; keep the first-only rule when `previous` is our own CLSID. `previous` is already in scope at that point.
- No unregister changes needed — the existing restore path (`:257-260`) already restores non-empty backups.

## Acceptance test
- Name: `re_registration_after_takeover_restores_the_new_handler_on_unregister` in the `TestRegistry` suite (`registration.rs:300-434`). Steps: fresh install (initial ShellEx `{OTHER}`) → register (backs up `{OTHER}`) → foreign takeover sets ShellEx `{OTHER2}` → re-register `-AllowOverwrite` → unregister. Assert final ShellEx default == `{OTHER2}`. Before the fix the assertion yields ShellEx deleted (empty) → red; after → green.
- Reuse: existing `TestRegistry` helpers used by `forced_registration_backs_up_and_restores` (:346-364) and `repeated_registration_keeps_the_original_backup` (:399-416); extend the latter — as written the "keeps the original backup" behaviour stays true only for `previous == ours`, which the new test makes explicit.
