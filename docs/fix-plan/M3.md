# parquet-viewer M3 — MIT/BSD licence texts of statically-linked crates are not distributed with the binaries

- Severity: medium
- Pinned SHA verified: `e815e646e6d261291417730ac79345da81e7f6f9`
- Status: **CONFIRMED** — `THIRD_PARTY.md:42-106` lists packages as `Package | Version | Licence` identifiers only; full texts are reproduced only for Zstandard (from `:242`) and Unicode (`:277`). Statically linked MIT/BSD crates include `snap` (BSD-3, entry `:91`), `brotli`/`brotli-decompressor`/`alloc-no-stdlib` (BSD-3), `lz4_flex`, `bytes` (`:35`, MIT). The distribution ships only `LICENSE NOTICE THIRD_PARTY.md` (`scripts/build-windows.sh:15`; same list at `scripts/build-windows.ps1:13-14`).
- Policy flag: **C2 (NOTICE rule for all repos — Manager decision pending; default proposal: "template first, then an optional third-party section")**. This spec's fix is compatible with either outcome of C2 because it operates on THIRD_PARTY files, not NOTICE itself.

- Depends on: C2 ruling for the final file naming/placement; the code-side steps can start immediately.
- Manager sign-off: not individually required beyond C2.

## Root cause
The licence audit so far checked allow-list membership (`cargo deny check licenses`), not notice-delivery obligations. MIT and BSD-3 require the copyright notice and licence text to be carried in binary distributions. `cargo deny` exiting 0 proves nothing about shipping texts, and `go-licenses`-style automation was never run for the Rust side.

## Fix (minimal)
1. Add `cargo-about` (or the equivalent templated generator the Manager prefers) with a template that emits full texts, producing `THIRD_PARTY_LICENSES.txt` (name subject to C2 ruling) over the *Windows target's* graph (`cargo about generate --target x86_64-pc-windows-gnu` — the shipped build target, matching `scripts/build-windows.sh`). Check the wheel licensing (`about.toml`) so only allow-listed licences pass and anything unusual fails the build.
2. Add the generated file to both build scripts' distribution copy lists: `scripts/build-windows.sh:14-16` and `scripts/build-windows.ps1:11-17`.
3. Add the file to the `SHA256SUMS` generation in both scripts.
4. Commit `about.toml` + template so the step is reproducible offline.

Alternative rejected: hand-curating each MIT/BSD text into `THIRD_PARTY.md`. Drifts out of sync with `Cargo.lock` on every dependency bump; generation is the same work done once.

## Acceptance test
- Test: CI step (or check script) `cargo about generate` runs clean and `THIRD_PARTY_LICENSES.txt` contains, verbatim, the BSD-3 block with `Copyright (c) 2015 Andrew Gallant` (snap uses BurntSushi naming — the fixer should assert on the actual text in the crate's LICENSE file at the locked version) and the brotli Dropbox copyright line. Fails before: the file doesn't exist. Passes after: strings present.
- Manual: run the build script, open `dist/`, confirm the new file ships next to `LICENSE`/`NOTICE`/`THIRD_PARTY.md` and the checksum list includes it.

## Risk / blast radius
- Very small: build tooling + a new shipped text file. No code touched. Watch for `cargo about` failing on crates with non-standard licence expressions — the tool's "no wheel" detection makes this fail loudly rather than silently omit (desired).
