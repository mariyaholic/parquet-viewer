# parquet-viewer L4 — `ThreadingModel=Both` on an object that owns HWNDs; should be `Apartment`

- Severity: low
- Pinned SHA verified: `e815e646e6d261291417730ac79345da81e7f6f9`
- Status: **CONFIRMED** — `registration.rs:217` `.set_string(&inproc_key(), "ThreadingModel", "Both")`; the object creates windows in `set_window` (`handler.rs:84-88`, `create_window` :373-445) and destroys them in `unload`/`Drop` (`destroy_window`, :262-277).
- With `Both`, an MTA client may call the object directly: window creation/destruction can then run on threads without a message pump, and `DestroyWindow` from a non-owning thread fails and leaks the window + `WindowContext`.
- Latent only today: prevhost runs STA, so no client exercises the MTA path.
- Size: S · Model effort: entry-level OK
- Depends on: none (one string + one test assertion).
- Manager sign-off: not required.

## Root cause
The threading model was written for the generic "in-proc server" default instead of matching the object's actual apartment affinity (it is a stateful, window-owning handler — Microsoft's preview-handler guidance registers `Apartment` for exactly this reason).

## Fix (minimal)
- `registration.rs:217`: `"Both"` → `"Apartment"`.
- Update the assertion in `fresh_registration_sets_values` (`registration.rs:314-317`) from `Some("Both")` to `Some("Apartment")`.

## Acceptance test
- Name: `fresh_registration_sets_values` (modified). Failed-before: existing test asserts `Some("Both")`, so pre-fix the modified test is red; post-fix green. Registry-level only — `TestRegistry`, runs anywhere the test suite runs.
- Manual on this PC (required, because apartment model must be observed in a real host): run the install script, open Preview Pane on a `.parquet`, and in Process Explorer confirm prevhost.exe runs STA and the preview renders (i.e., `Apartment` doesn't break Explorer's calling pattern).

## Risk / blast radius
- Minimal code risk; registry-value change means previously registered users must re-register (the installer already overwrites values on register; the unregister path deletes the whole CLSID tree, so a clean re-register leaves no stale `Both`).
- None of the other findings depend on the model value; if H1/M1 untests reveal resize churn, re-verify once after all handler-code findings land.
