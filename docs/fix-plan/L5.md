## Root cause
The COM surface was implemented to the minimum the preview pane needs to *display*; the integration surfaces Explorer actually drives (site/frame for keyboard focus, visuals for theme/font) were stubbed. The pane therefore can't be tabbed into, ignores dark mode and Explorer's font, and renders the non-scalable system bitmap font on high-DPI displays.

## Fix (minimal, three independent sub-steps)
1. **Keyboard focus (IObjectWithSite):** new vtable struct + QI entry in `com.rs` (pattern to copy: `IPreviewHandlerVisualsIfc` + `refcount_bridge!` at `com.rs:68-77`/:170-217; extend `ComObject` fields :80-89 and the QI match :154-164, `new_handler` :340-357). `SetSite` stores the site; QI it for `IPreviewHandlerFrame`; `translate_accelerator` (`com.rs:307-320` + `handler.rs:218-224`) forwards unhandled keys via that frame and returns what it returns (fail-closed: with no site, keep `S_FALSE`).
2. **Font:** in `visuals_set_font` (`com.rs:322-338`), store the HFONT and post it to the edit with `WM_SETFONT` (needs `WM_SETFONT` added to `ffi.rs`); fallback `GetStockObject(DEFAULT_GUI_FONT)` at window creation when no visual set yet.
3. **Colours:** `SetBackgroundColor`/`SetTextColor` values stored; apply via `WM_CTLCOLORSTATIC` in `window_proc` (`handler.rs:373-529`, return the stock NULL_BRUSH pattern for the edit background so Explorer's colour shows).
- Explicitly out of scope for this spec: DPI/paging (v2), every visual property beyond the three implemented today.
