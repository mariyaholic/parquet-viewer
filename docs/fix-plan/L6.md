## Root cause
Round 2 reversed the "prune empty keys" behaviour but left its dead API and its test in place; and the Windows-specific safety code (kill, QI, cancel) has no automated test that actually runs it, so the deployment-of-tests mirrors Wine's blind spots at code level.

## Fix (minimal)
1. **Delete the dead API:** remove `delete_empty_key` from the `Registry` trait (`registration.rs:78-84`), both impls (`win32_registry.rs:22-26`, `TestRegistry` :141-143), its call site (`registration.rs:266-274`), and the tautological test (`win32_registry.rs:160-171`).
2. **Kill test cross-platform:** replace the `#[cfg(target_os = "linux")]` guard in `worker/tests/client.rs:68-83` with a Windows branch that verifies termination by `OpenProcess` + `WaitForSingleObject(handle, 0)` returning WAIT_OBJECT_0 (needs `WaitForSingleObject`/`GetExitCodeProcess` declared in `ffi.rs`; `ffi.rs` does not have them today).
3. **End-to-end COM harness** (new test, `#[cfg(windows)]`, opt-in build step): `CoCreateInstance` the CLSID from the built DLL, `Initialize` with an `SHCreateMemStream` over `tests/fixtures/trades.parquet`, `SetWindow` on a hidden test HWND, `DoPreview`, wait `WM_APP+1`, then `Unload` → Release → assert edit text non-empty, no worker process left, no spool temp file left. This harness is the fixture L5/M1 reuse.
- Rejected alternative: skipping the COM harness and keeping only unit tests. The three medium findings above all sit in code no unit test can reach; the harness is what prevents the next "only Wine tests ran" class of miss.

## Acceptance test
- Itself a test deliverable; each part is fails-before by construction: (1) `cargo build` previously succeeded with the no-op — after removal, any *other* trait-missing impl fails loudly; (2) the kill test on Windows fails before (asserts nothing → make it fail by asserting exit code 1 explicitly, which the un-killed process won't be) and passes after the existing kill logic runs; (3) harness test: before H1/M2/L5 fixes it would already show symptoms (e.g., LF blob, wait — not in THIS spec's scope).

## Risk / blast radius
- Removing a trait method touches every implementor (2 impls). Lowest-risk item in the batch.
- The COM harness must not auto-run Everywhere: builder-gated (needs the built DLL in env `PATH`/var). Decide: run only on Windows CI runners and locally, never Wine.
